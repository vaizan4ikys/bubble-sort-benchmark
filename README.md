# Bubble Sort Benchmark

Reproduction package for *Experiment 1* of **Experimentation & Evaluation 2026** (Prof. G. Bavota, G. Crupi):
which of three Java bubble-sort implementations should *Bubble Inc.* ship in its library?
The only criterion is running time.

Authors: Pavlo Harabadzhiiev, Vladyslav Nechaiev.
The work was done with the help of an AI assistant (Claude Code), which is allowed by the course.

| Candidate | Idea |
|---|---|
| `BubbleSortPassPerItem` | always `n` passes of `n-1` comparisons |
| `BubbleSortUntilNoChange` | stops after the first pass without a swap |
| `BubbleSortWhileNeeded` | stops early *and* shrinks every pass to the position of the last swap |

The three sorters in `src/exp01/` are the files provided with the assignment, **unchanged**.

## Experiment in one paragraph

A full-factorial, repeated-measures design: **3 algorithms x 6 input orders x 6 input sizes** (108 cells).
Every cell is measured in 10 *forks* (a fork is a fresh JVM); each fork warms up the JIT compiler, then times
30 batches of sorts (batching makes sub-microsecond sorts measurable) and verifies, outside the timed region,
that every result is sorted. All three algorithms receive exactly the same input data within a fork index, and the
order of the 1 080 jobs is shuffled with a fixed seed. The pre-registered hypotheses are in
[`HYPOTHESES.md`](HYPOTHESES.md) (committed at 01:16:35 on 4 November 2026, before the harness was committed and before any main-experiment data existed; a short pilot with an uncommitted early harness followed a minute later, see the report, Section 2.4).

## Reproduce

Requirements: a JDK (main experiment: Homebrew OpenJDK 26.0.1), Python 3 with the packages in
`requirements.txt`; for the JMH step Maven. The queue scripts call `.venv/bin/python`:

```sh
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

Build the classes (`bin` for the main experiment, `bin_ext2` for the follow-ups; `--release 8` so that the
JDK 8 follow-up can load them):

```sh
javac -d bin src/exp01/*.java
javac --release 8 -d bin_ext2 src/exp01/*.java
cp -r bin_ext2 bin_ext
java -cp bin exp01.OperationCounter results/operation_counts.csv
```

Main experiment (about 80 minutes; close heavy applications, keep the laptop on AC power; the run was
started with `caffeinate -dims`):

```sh
scripts/capture_environment.sh results/full/environment.txt
caffeinate -dims .venv/bin/python scripts/run_experiment.py --out results/full --forks 10 --iters 30
```

Follow-ups (several hours, run one after the other on an otherwise idle machine). Queue 2 expects
Homebrew `openjdk@17/21/25` and Corretto 8; other locations can be set with `JDK_PREFIX` and `JAVA8_BIN`:

```sh
caffeinate -dims scripts/run_followups.sh
caffeinate -dims scripts/run_followups2.sh       # includes run_cold.py, run_jmh.sh and remeasure.py
caffeinate -dims scripts/run_followups3.sh
.venv/bin/python scripts/pool_remeasure.py
```

Steady-state re-measurement of the full design (about one hour; same JDK as the main run; `SteadyWorker`
warms up the loop that runs the timed batches, see Section 3.7 of the report):

```sh
javac -d bin_steady src/exp01/*.java
scripts/capture_environment.sh results/steady/environment.txt
caffeinate -dims .venv/bin/python scripts/run_experiment.py --out results/steady --worker steady --classes bin_steady \
  --forks 3 --iters 30 --jvm-extra=-Dexp01.minStabMs=8000
.venv/bin/python analysis/analyze_steady.py
```

Real JDK 25 on the main laptop (Temurin 25.0.5; compiled with the same JDK):

```sh
J25=/Library/Java/JavaVirtualMachines/temurin-25.jdk/Contents/Home/bin
$J25/javac -d bin_jdk25 src/exp01/*.java
.venv/bin/python scripts/run_experiment.py --out results/ext_jdk25_real --classes bin_jdk25 --types Integer \
  --java $J25/java --sizes 1000 5000 10000 --forks 5 --iters 20
```

Other computers: see "Task: check on a second machine" below.

Analysis and report (in this order; every script reads only `results/` and earlier outputs):

```sh
.venv/bin/python analysis/analyze_main.py
.venv/bin/python analysis/decision_metrics.py
.venv/bin/python analysis/analyze_followups.py

```

`results/*/raw.csv` columns: `seq` (position in the shuffled job order), `algorithm`, `order`, `size`, `fork`,
`iter` (timed batch), `batch` (number of sorts in the batch), `ns_per_sort` (batch time / batch size),
`gc_during` (a garbage collection happened inside the timed region), `warmup_sorts`, `warmup_timeout`.
Follow-ups that use `ExtendedWorker` have an additional `type` column; `results/steady/raw.csv` (`SteadyWorker`) has the additional columns
`stab_rounds` (batches run before the timed ones) and `stab_converged` (1 = the stabilisation criterion was met).

## Measurement procedure (per fork)

1. Generate the input from `(base seed, order, size, fork)`.
2. Warm-up: sort fresh copies one at a time until at least 20 sorts and 1.5 s have passed and the median time has
   stabilised (<5 % change) - tiny sorts only need the minimum time.
3. Calibrate a batch size B so that one timed batch takes about 2 ms.
4. Two untimed batches, then 30 timed batches. Per batch: copy B arrays (untimed), time `sort` on all of them,
   verify they are sorted (untimed). Recorded value: batch time / B.
5. JVM flags: `-Xms2g -Xmx2g -XX:+UseSerialGC` (no concurrent GC threads, fixed heap).

## Repeating the reduced design on another computer

The main data come from one Apple M3 Pro laptop (ARM). The reduced design (6 input orders × sizes 1 000 / 5 000 / 10 000
× 3 algorithms × 5 forks = 270 JVM runs, about 35 minutes) can be repeated on any computer; it was run on a second M3 Pro
(`results/portable_vlad-laptop/`, macOS 27, JDK 25.0.1) and on an x86 desktop (`results/portable_at3eus-pc*/`, Ryzen 5 5600,
Windows 11; the JDK 17 run there has decimal commas from an earlier script version and is repaired in memory by the analysis).

1. Install a JDK (any version ≥ 8), Python 3.7+ and Git. On Windows, tick "Add to PATH" in the installers.
2. `git clone https://github.com/vaizan4ikys/bubble-sort-benchmark` and enter the folder.
3. Check that the computer is ready (about 10 seconds, nothing is saved):
   - Windows, native and not WSL (WSL adds a virtualisation layer): `run_windows.bat windows-x86 --check`
     (in PowerShell: `.\run_windows.bat windows-x86 --check`)
   - macOS / Linux: `scripts/run_portable.sh linux-x86 --check`
4. Plug the computer in, close other programs, and start the same command without `--check`.
   Do not use the computer or close the lid until it finishes. If it is interrupted, the same command resumes it.
5. The folder `results/portable_<name-of-the-machine>/` contains the raw measurements and an `environment.txt`
   with the hardware and Java version; `analysis/analyze_machines.py` compares it with the other runs.
